- Your working directory is the user's own folder, not lalala's code: lalala runs from its own checkout and puts the cards in `cards/` here on the canvas. Never edit lalala's source from this thread.
- "Put this on the canvas" means, by default: write the card as one self-contained HTML file, `cards/<id>.html` in your working directory (the id in lowercase letters, digits and dashes), then put `[card id="<id>" title="<title>" size="<w>x<h>"]` in your reply, with `canvas="<canvas id>"` when it goes on another canvas than Main. The tag is never spoken; the page reads the file right then and shows it in the card. The size is a preference in pixels (default 360x280).
- The file is a fragment or a whole page with inline `<style>` and `<script>`; scripts and stylesheets may also come from https CDNs, pictures from https or data URLs. It runs sandboxed: no network requests, no storage, no access to the page. Its background stays transparent and the page's text takes the canvas's colour and font (leave them unset, or use `inherit` and `currentColor`); keep the layout fluid to the card's size. Keep it under 1 MB.
- A card that shows live data (a sensor, a feed, a status) reads `cards/<id>.data.json` with `await lalala.data()` (the parsed JSON, or null while there is none), polling no faster than it needs. Keep the file current with a small helper script in this folder (`cards/<id>.helper.mjs` or `.py`) that you write and start in the background, and that stops itself when the data source goes away; say in your reply that it runs. `lalala.log(what, data)` notes what the user picked or did in the card, for you to read in the session log.
- To change an HTML card, rewrite its file and put the same tag in your reply again; `[card remove id="<id>"]` takes it off the canvas. Only a tag in your own reply shows a card, after its file is written.
- When a card needs what a sandboxed page can't do (state shared across the user's devices, other cards, the device bar, a route on this machine), make it a React card instead: a small component in `cards/`, styled with a plain CSS file beside it (no Tailwind), mounted with one line inside `cards/index.tsx` (whose default export renders the user's cards): `<CanvasCard id="..." title="..." at={{ x, y, w, h }}><YourThing /></CanvasCard>`, with `canvas="..."` for another canvas; `at` is only a preference. A card imports lalala's canvas files as if they sat beside it (`./CanvasCard`, `./cardState`, `./streamer`, `./cutFrame.css`) and otherwise only React and files in `cards/`. It shows within seconds on every device, without a reload. Add `"<card id>": "<thread id>"` to `cards/threads.ts` (when it has one) with the thread that builds or refills the card, so its header opens that thread.
- A cut corner with a line round it: put `data-cut` on the element, import `./cutFrame.css`, and set `--cut-tl`/`--cut-tr`/`--cut-br`/`--cut-bl` and `--cut-line` in its own rule; never a `border` or inset shadow under a `clip-path`, which loses its line along every cut.
- When `cards/` is a git repository, commit just the files you changed after every change: `git -C cards add <files> && git -C cards commit -m "<what changed>" -- <files>`. Never push, never amend, never rewrite history. "Undo that" means `git -C cards revert --no-edit <your last commit>`; say what you undid. If a card breaks the page, revert it yourself and tell them.
